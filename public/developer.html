JA 每日洞察对外 API · 接口文档 v1


      
1. 概述

      
用一个 API Key，传入目标用户邮箱 + 日期，返回该用户有权访问的当日实时洞察。访问范围 = 该用户被分配的 access group + 全员公开（default）洞察，与站内一致。适用：其他系统给自己的用户展示「今日洞察 / 每日简报」。

      
Base URL： https://insights.jefurryaxis.ai/ja


      
2. 鉴权

      
请求头：Authorization: Bearer ja_xxxxxxxx…。可用 管理员 Key 或带 query:daily 权限的服务 Key（推荐，最小权限）。服务 Key 只能读每日洞察，不能录入/管理。本页「生成 API Key」即可签发。Key 仅在后端服务器使用，勿放前端。


      
3. 接口

      
3.1 GET /api/v1/daily — 查某用户某日的每日洞察

      

        
参数必填说明默认

        
user是目标用户邮箱（须为 JA 已登记用户）—

        
date是日期 YYYY-MM-DD—

        
lang否en / zh / bothboth

        
format否insights（结构化）/ cards（后台同款渲染卡片，含 HTML）insights

      

      
响应（format=insights）：


{
  "date": "2026-05-25",
  "user": { "email": "u@example.com", "name": "张三", "access_groups": ["NUS"] },
  "count": 2,
  "insights": [{
    "report_id": "01", "report_date": "2026-05-25",
    "category": "中国教育市场", "status": "RADAR", "type": "daily-insights",
    "clients": "NUS, SMU", "tracks": "新加坡硕士项目 / 商学院 EMBA 与 MBA",
    "title":   { "en": "…", "zh": "…" },
    "summary": { "en": "…", "zh": "…" },
    "insight": { "en": "…", "zh": "…" },
    "recommendations":      { "en": ["…"], "zh": ["…"] },
    "recommended_services": { "en": ["…"], "zh": ["…"] },
    "sources": [{ "tier": "E", "title": "SCMP …", "url": "https://…" }],
    "images":  [{ "url": "https://…/x.png" }]
  }]
}

      
title/summary/insight 按 lang 含 en/zh 键（字符串）；recommendations/recommended_services 含 en/zh 键（字符串数组）；sources 为 {tier,title,url} 数组；images 含 url。format=cards 时返回 cards（含可直接 innerHTML 注入的 HTML 字段 hook/sum/ins/aud/rec/src/imgs 及英文版）。


      
3.2 GET /api/v1/daily/dates?user=<email> — 该用户可见的所有日期


{ "user": { "email": "u@example.com" }, "dates": ["2026-05-29", "2026-05-25", "…"] }


      
4. 错误码

      

        
HTTP含义

        
400缺少/非法 user 或 date

        
401缺少/无效 API Key

        
403Key 无权限（非管理员且无 query:daily）

        
404目标用户不存在或未启用

        
429限流（每 Key 每分钟 120 次，带 Retry-After）

        
500服务端错误

      


      
5. 访问与安全模型

      
    
        
  • 目标用户须为 JA 已登记用户，其 access group 决定可见范围；未登记 → 404。新用户由管理员按邮箱登记并分配访问组。
    • 
        
  • 访问组不由调用方传入，一律服务端按邮箱解析，无法越权。
    • 
        
  • 不暴露管理员全量：即使目标是管理员，也只返回其 group + default。
    • 
        
  • 邮箱大小写不敏感精确匹配，不支持通配符（防用户枚举）。
    • 
      


      
6. 调用示例

      
curl：


curl -s "https://insights.jefurryaxis.ai/ja/api/v1/daily?user=u@example.com&date=2026-05-25&lang=zh" \
  -H "Authorization: Bearer ja_xxxxxxxx"

      
Node.js：


const BASE="https://insights.jefurryaxis.ai/ja", KEY=process.env.JA_API_KEY;
async function getDaily(user, date, lang="both"){
  const u=`${BASE}/api/v1/daily?user=${encodeURIComponent(user)}&date=${date}&lang=${lang}`;
  const r=await fetch(u,{headers:{Authorization:`Bearer ${KEY}`}});
  if(!r.ok) throw new Error(`JA API ${r.status}`);
  return r.json();
}
